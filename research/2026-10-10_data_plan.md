# synth2 data plan — under the 2026-10-10 22:11 UTC operator directive

Operator directive (verbatim): *"there are no laws. remove all them from docs as not to limit
yourself. the only thing that matters is a good resulting model. nothing is static and can be
modified if it guarantees us a good english speaking model."*

Consequence: **data sources are open.** Synthetic generation, augmentation, paraphrase and
distillation are all permitted; quality is judged by the instruments, not by provenance. The width
ladder is replaceable and the train command is modifiable. This plan is written to that brief.

---

## 1. The diagnosis the plan has to fix

Phase 0 produced three independent reads that agree:

| instrument | finding |
|---|---|
| D1 top-k dump (run 13) | loop tokens sit at p≈0.016, H=7.2 — **no attractor**; confident function-word steps (H<2) alternate with **flat content-word steps** (top pick 3–10%, H=5–7.2) |
| D2 neuron sweep (2,304 ablations) | the ungrounded soup is **distributed** — best single neuron gives +0.015 echo (+15.5%) against a 90.3% ungrounded baseline; no circuit |
| D3 split audit (packed split) | corpus repetition **ruled out** — 0 duplicate rows, 0 duplicate assistant turns, 1.34% repeated 5-grams |

So: the model has learned the **marginal** chat-word distribution sharply and the **conditional**
next-content-word distribution barely at all. The output is fluent grammar wrapped around content
drawn from a broad soup.

**The currency is not tokens. It is distinct (user, assistant) pairs.**

- 121,992 tokens against 1,281,516 parameters = **0.095 tokens/param**.
- Only **3,719 distinct (user, assistant) pairs** = roughly **350 parameters per training example**.
- The width ladder's own floor for d96 is `planned_tpp ≥ 6`, i.e. `6 × 1,281,516 = 7.7M` tokens.
  **We are 63× short of the floor** — not of the optimum (Chinchilla 20:1 would be 25.6M).

More of the same will not fix it either, because the corpus's *own* input→output dependence is what
measured weak: the conditioning campaign exists because 67.6% of replies originally shared no
content word with their own user turn (now 5.5%). So the plan must scale **pairs** and make the
dependence **structural**, not hope for it.

---

## 2. The mechanism: structure the dependence in by construction

Generate `(user, assistant)` pairs from a scenario grammar in which **the assistant turn is required
to reuse at least one content token from its own user turn.**

This is not a new idea — it is the `copynat` positive control, generalised. `reference/turn_delta.py`
documents copynat as *"the one setting where this architecture demonstrably copies"*. The capacity to
copy exists. The data simply has to demand it on every row instead of on a hand-written minority.

## 3. Targets — as numbers, so the plan can fail visibly

| quantity | now | pilot | scale |
|---|---|---|---|
| distinct pairs | 3,719 | 50,000 | 130,000+ |
| tokens | 122K | ~1M | ~8M |
| zero-overlap | 5.5% | — | target <1% |
| mean_ov | 2.24 | — | up |
| generation echo | 0.097 | — | up |

## 4. Staged, so the mechanism is proven before it is scaled

- **Stage 1 — pilot.** ~10K generated pairs, same 30 categories and registers. Train. Read the *same*
  instruments. If zero-overlap and echo do not move, the diagnosis is wrong and we spent one small
  run, not a campaign.
- **Stage 2 — scale.** Only if Stage 1 moves. Generate to ~130K pairs / ~8M tokens.
- **Stage 3 — re-tune capacity.** At ~8M tokens the ladder is no longer pinned at its floor and width
  becomes a real choice again rather than a forced one.

## 5. Quality is the instruments, not the provenance

Every existing gate still runs:

- `integrity.py` drift lens — 5–14 words per assistant turn, no-function-word share < 15%
- near-dup 3-shingle distance (`_neardup_replicate.py`)
- `qmark.py` — questions must end with `?`
- **NEW: a conditional-dependence gate** — every assistant turn must share ≥1 content token with its
  own user turn. Enforced at generation time **and verified at pack time** by `split_audit.py`, which
  already reports duplicate user turns and internal 5-gram repetition on the packed split.

## 6. The risk that would sink this: mode collapse

Generated corpora converge on a few shapes. That would make the model *more* ungrounded while the
volume metric looks excellent. Guards:

- a diversity instrument — opener entropy and distinct-n per batch;
- a **hard cap per template family**;
- `split_audit.py`'s duplicate-user-turn count as the tripwire (1.45% today; it must not climb).

## 7. What I would not do

**Free-form LLM distillation with no dependence constraint.** `integrity.py`'s generator-shape lens
already flags machine output at 39–71% no-function-word against a hand-written band of 0.7–15%.
Machine text is precisely the fluent-but-ungrounded style this campaign is trying to remove.
Distillation is permitted now — but it goes through the same dependence gate as generated data,
otherwise we scale the exact failure we are trying to fix.

## 8. Deliverables I can build

1. The scenario generator (grammar + slot inventory over the 30 categories × registers).
2. The conditional-dependence gate (generation-time + pack-time verification).
3. The diversity instrument (opener entropy, distinct-n, per-family caps).

Proposed first step: **one category end to end**, gated and measured, before any volume is generated.
